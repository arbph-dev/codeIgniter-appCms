
## 1. Les trois couches actuelles

Tu as maintenant une séparation assez nette :

- **CSS** → comportement responsive et affichage
- **HTML** → structure `nav > nav-article > header-row > title + toggle > toc`
- **JS** → ouverture de la sidebar + ouverture de chaque accordéon

Le JS attache bien un listener à chaque `.nav-toggle`, récupère le parent `.nav-article`, bascule la classe `open` et met à jour `aria-expanded`. Donc cette partie est correcte.

La structure HTML correspond bien à ce que le CSS attend : `.nav-toggle` est dans `.nav-header-row`, elle-même dans `.nav-article`, et `.nav-toc` est le sibling suivant.

# 2. Point important : ton CSS a un problème de couleur

Je pense que c'est actuellement **le premier problème structurel visible**.

Tu définis :

```
nav {
  background-color: var(--bg-sidebar);
}
```

Mais tu ne définis pas explicitement la couleur du texte du menu.

Ensuite :

```
.nav-article .nav-title {
  color: inherit;
}
```

et :

```
.nav-article .nav-toggle {
  color: inherit;
}
```

Le `color` est donc hérité.

Or `body` définit :

```
body {
  color: var(--text-main);
}
```

Donc ton menu sombre hérite probablement de :

```
--text-main
```

qui est une couleur sombre.

Pour le thème marine :

```
sidebar : #0f172a
texte   : #334155
```

Donc :

```
bleu très sombre
sur
bleu très sombre
```

Cela explique potentiellement plusieurs impressions visuelles :

- hover peu perceptible ;
- chevron peu visible ;
- liens du menu insuffisamment contrastés.

Je mettrais explicitement la couleur du menu :

```
nav {
  background-color: var(--bg-sidebar);
  color: var(--text-header);
}
```

Ou, mieux à terme, une variable dédiée :

```
--text-sidebar: #f8fafc;
```

Puis :

```
nav {
  color: var(--text-sidebar);
}
```

C'est à mon avis le premier correctif à faire.

# 3. Le fonctionnement mobile est techniquement correct

Ton CSS mobile dit :

```
.nav-article .nav-toc {
  display: none;
}

.nav-article.open .nav-toc {
  display: block;
}
```

Et ton JS fait exactement :

```
const article = button.closest('.nav-article');
const isOpen = article.classList.toggle('open');
```

Donc la chaîne est :

```
clic chevron
    ↓
.nav-toggle
    ↓
.closest('.nav-article')
    ↓
classList.toggle('open')
    ↓
.nav-article.open
    ↓
.nav-toc display:block
```

C'est bon.

Si, sur téléphone, tu ne voyais auparavant que :

```
Accueil du portail              >
```

sans pouvoir ouvrir, le problème pouvait être :

1. ancien JS non chargé ;
2. erreur JavaScript précédente interrompant l'exécution ;
3. CSS différent réellement chargé ;
4. problème de clic/overlay.

Mais **dans les trois fichiers que tu viens de montrer**, l'accordéon lui-même est correctement câblé.

# 4. Point à surveiller : ton JavaScript peut être interrompu avant le menu

Dans ton fichier JS, il y a beaucoup de code historique.

Par exemple :

```
stack = document.getElementById("stack")
sidebarList = document.getElementById("sidebarList");
```

Or `sidebarList` n'existe plus dans le HTML actuel puisqu'il est commenté.

Cela ne pose pas problème directement :

```
sidebarList = null
```

Mais ton code contient encore des fonctions liées à cet ancien système.

Le vrai point à surveiller est que toute erreur JavaScript dans :

```
DOMContentLoaded
```

avant :

```
document.querySelectorAll('.nav-toggle')
```

empêcherait l'initialisation des accordéons.

Dans le code visible, je ne vois pas d'erreur évidente qui empêcherait cette partie de s'exécuter. Le listener du chevron est bien placé en fin d'initialisation.

# 5. Problème architectural actuel : deux systèmes de navigation coexistent

C'est probablement le point le plus intéressant avant de regarder CodeIgniter.

Ton JS contient encore l'ancien système :

```
pages
sidebarList
switchTab()
createPanel()
panel-card
```

Alors que ton HTML actuel commence à évoluer vers :

```
Article
 └── Table des matières
      ├── Bienvenue
      │    ├── But
      │    ├── Présentation
      │    └── Motivations
      │
      ├── Actualités
      │
      └── Environnement
```

Ce sont deux modèles très différents.

### Ancien modèle

```
Sidebar
    ↓
LI data-index
    ↓
switchTab(index)
    ↓
masquer / afficher panel-card
```

### Nouveau modèle

```
Article
    ↓
nav-title
    ↓
nav-toc
    ↓
data-target-id
    ↓
navigation vers une section d'article
```

Le second correspond beaucoup plus à ton architecture CMS actuelle.

D'ailleurs ton HTML possède déjà :

```
data-article-id="tab1"
```

et :

```
data-target-id="tab1--bienvenue"
```

Ce qui montre clairement que la navigation est en train de passer du prototype :

```
Tableau de bord / Paramètres / Diagnostic
```

vers :

```
Article CMS / Sections / ancres
```

# 6. Mon diagnostic sur le CSS actuel

Je classerais les choses ainsi.

### Correct

- mobile first ;
- sidebar off-canvas ;
- `nav.open` ;
- fermeture ;
- zone tactile séparée titre/chevron ;
- dropdown desktop ;
- accordéon mobile ;
- `z-index` raisonnable ;
- menu principal en flex.

### À corriger

#### A — couleur explicite de la navigation

```
nav {
  color: var(--text-header);
}
```

C'est prioritaire.

---

#### B — état hover/focus

Le hover existe maintenant, mais il est basé sur :

```
rgba(255, 255, 255, 0.12)
```

Ce qui fonctionne pour un menu sombre.

Il faudra néanmoins probablement un vrai système :

```
normal
hover
active
current
focus
```

Car actuellement :

```
.nav-title.active
```

signifie visuellement quelque chose, mais il faudra déterminer ce que représente réellement `active` dans ton CMS.

Est-ce :

- l'article actuellement affiché ?
- le menu actuellement ouvert ?
- la page courante ?
- le portail ?

Ce n'est pas encore clair, et c'est important avant de connecter le menu aux vues CodeIgniter.

---

#### C — le dropdown desktop peut être simplifié

Ton ancienne version avait un "pont" invisible entre le menu et le dropdown.

La nouvelle version l'a supprimé :

```
top: 100%;
```

C'est mieux.

Comme le dropdown commence directement sous `.nav-article`, tu n'as normalement plus besoin du pseudo-élément de pont.
