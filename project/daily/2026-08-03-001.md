"Workbench – Stage 2".

Le Stage 1 est considéré comme terminé et validé.

## Objectif du Stage 2

Consolider l'architecture Workbench afin d'obtenir une infrastructure homogène, réutilisable et prête à accueillir tous les futurs Workbench de la plateforme (Versatile Knowledge Base, ModelWorkbench, SceneWorkbench, LightWorkbench, etc.).

Le Stage 2 n'a PAS pour objectif d'ajouter de nouvelles fonctionnalités métier. Il consiste à stabiliser les contrats, factoriser les composants communs et préparer le Stage 3 (authentification).

Le Stage 1 est gelé : toute amélioration identifiée sera bufferisée si elle ne fait pas partie des objectifs du Stage 2.

## Décisions déjà validées

### D015 — Contrat d'un Panel

Responsabilités :
- construire son DOM (render())
- afficher un modèle (show())
- gérer ses états (clear(), showLoading(), showError())
- notifier le Workbench via callbacks

Un Panel :
- ne fait jamais d'appel API
- ne contient aucune logique métier
- ne connaît pas les modèles métier

Contrat :

constructor()
render()
show(data)
clear()
showLoading() (si nécessaire)
showError(msg) (si nécessaire)
destroy()

---

### D016 — Contrat d'un Workbench

Responsabilités :
- construire le layout
- instancier les Panels
- appeler les Services
- maintenir l'état courant
- coordonner les Panels

Un Workbench ne contient pas de logique HTML détaillée.

Squelette attendu :

bootstrap()
createLayout()
createPanels()
bindEvents()
load()
destroy()

## Objectifs détaillés du Stage 2

1. Harmoniser définitivement tous les Panels.

2. Harmoniser définitivement tous les Workbench.

3. Factoriser les composants UI réutilisables.

4. Mettre en œuvre l'Orchestrated CSS Reuse Strategy.

Réutiliser autant que possible les styles existants entre :

- assets/css/components/workbench.css
- app/Views/workbench/mot.php

Réemploi prévu :

| Besoin | Réemploi |
|--------|----------|
| header panel | .wb-toolbar |
| boutons | .wb-btn |
| table | .wb-tree-node |
| détail | .wb-inspector-body |
| dl/dt/dd | .wb-dl |
| état vide | .wb-empty |
| pagination | .wb-btn + .wb-btn--active |

Le CSS réellement nouveau doit être limité à :

- layout grid
- zones panels
- search dark
- adaptation cp_table

5. Uniformiser les Services.

6. Préparer la réintégration future de l'authentification sans encore la réaliser.

## Contraintes de travail

- Réponses courtes.
- Pas de code tant qu'il n'est pas demandé explicitement.
- Toujours commencer par l'analyse de l'impact.
- Toute amélioration hors périmètre est bufferisée.
- Une réflexion d'architecture est réalisée à la fin de chaque étape significative avant de poursuivre.

Principe du projet :

"Raw is beautiful."

Nous privilégions une architecture simple, lisible et évolutive ("une pyramide plutôt qu'un escabeau").
