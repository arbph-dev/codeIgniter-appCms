AUTH CONTRACT

Web UI 	-> session Shield
API 	-> token Shield

api/* échappe au filtre Session mais est géré par token
'session' => ['except' => [
    ...
    'api/*',
]]


|Endpoint|Fonction|Orbis|
|---|---|---|
|`POST /api/auth/login`|établir l'authentification|`AuthProvider`|
|`GET /api/auth/me`|connaître l'utilisateur courant|**`ProfileClient`**|
|`GET /api/auth/profile`|profil actuellement exposé par le contrôleur|à analyser|
|`POST /api/auth/logout`|invalider la session/token|`AuthProvider`|
|`POST /api/auth/register`|création de compte|futur|



─────────────

POST /api/auth/login
    public
    → token
    → user initial

GET /api/auth/me
    token obligatoire
    → identité courante
    → groups
    → permissions

POST /api/auth/logout 
    token obligatoire
    → révocation token
logout est correctement placé derrière tokens

POST /api/auth/register
    actuellement désactivé

─────────────
GET /api/auth/profile
    présent
    mais non protégé
    informations incomplètes
    → à clarifier / probablement supprimer ou réaffecter

─────────────

profile() est incohérent avec me()
/api/auth/me est actuellement la seule route Auth explicitement protégée par le filtre tokens dans cette configuration.
me() est exactement ce dont Orbis a besoin, le contrat métier est déjà là :

$user = auth('tokens')->user();

if (!$user && auth()->loggedIn()) {
    $user = auth()->user();
}

puis :

[
    'id'          => $user->id,
    'username'    => $user->username,
    'email'       => $user->email,
    'groups'      => $user->getGroups(),
    'permissions' => $user->getPermissions(),
]




GET /api/auth/profile n'est pas protégé dans Filters.Legacy / doublon à traiter.

profile() renvoie seulement : id , username , email , groups. Il manque : permissions
il n'y a pas le contrôle explicite :

if (!$user) { return 401; }
si la route était appelée sans utilisateur token valide, le comportement dépendrait ensuite de ce que retourne auth('tokens')->user() et de l'accès aux propriétés.

```py
class ProfileClient(BaseApiClient):

    def __init__( self, auth, timeout: int = 10, save_samples: bool = False,):
        super().__init__( ZEALOT_BASE, auth=auth, timeout=timeout, save_samples=save_samples,)

    def me(self):
        return self.get("/api/auth/me")
```


ProfileClient ne doit absolument pas refaire le login.
ProfileClient ne doit pas devenir un client d'administration des utilisateurs.
On n'a pas besoin de construire un système User/Group/Permission côté Orbis. Le serveur possède déjà le concept.

Le menu pourrait ensuite avoir quelque chose de ce genre :
```py
auth = get_auth(store, service)

if auth:
    profile = ProfileClient(auth)
    me = profile.me()
```
