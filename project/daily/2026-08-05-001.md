# Phase C — WorkbenchView
## LayoutDescriptor.js 
objet de config par Workbench (zones, css)
- une seule fonction createDescriptor(). Elle valide, gèle l'objet (Object.freeze), et retourne.
- Le gel est intentionnel : un descripteur ne se modifie pas à l'exécution.
- les zones ont des noms CSS explicites (wb_mot_left, wb_mot_right) qui ne se dérivent pas mécaniquement du layout. le descriptor doit les porter

WorkbenchView
- layout + montage/démontage des Panels

WorkbenchView absorbe :
- createLayout() construit le layout + les zones via innerHTML.
- createPanels() sélectionne ces zones par classe CSS et y appende les panels. 

WorkbenchView.js — quatre méthodes publiques. 
- build() crée le DOM. mountPanels() appelle panel.
- render() et appende.
- unmountPanels() vide les zones sans toucher aux panels.
- getZone() pour accès direct si besoin. C'est tout.

La migration de MotWorkbench est un diff de 15 lignes. 
- createLayout() disparaît entièrement.
- createPanels() perd les deux getElement().
- bindEvents() et load() sont zéro touche.
