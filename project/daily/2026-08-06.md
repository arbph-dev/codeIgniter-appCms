# VKB Workbench — Plan de développement

## Infrastructure (Stage 2.1 — validé)

### Front
```
core/
    WorkbenchBase       init, renderStructure, getElement, bus
    PanelBase           contrat render / show / clear / destroy
    WorkbenchView       layout, zones, mount / unmount panels
    LayoutDescriptor    config immuable par Workbench
    ComponentRegistry   registre init composants (tabs / flat)

shared/
    templates/
        toolbar.template    header panel + bouton optionnel
    validation/
        rules               required, minLength, maxLength, pattern, email, phone, date
        validator           validate(), validateAll()
    Form                    PropertySet → champs, validation, extract, ComputePropertySet
```
Référence de l'architecture : MotWorkbench (list + detail, CRUD complet, pagination, recherche).



Modèle de développement par Workbench
1. service.js          appels API (fetch, save, delete)
2. PropertySet         schéma déclaratif des formulaires
3. ListPanel           extend PanelBase
4. DetailPanel         extend PanelBase
5. Workbench           LayoutDescriptor + WorkbenchView + bindEvents




CSS
workbench.css + theme_one.css (palette article.css, plein écran)

### Backend
Pour ces Worbench le backend est simple

- refactoring/app/Config/Routes.php
```php
$routes->group('workbench', ['namespace' => 'App\Controllers'], static function ($routes)
{
    $routes->get('component-catalog'    ,   'WorkbenchController::componentCatalog' );
    $routes->get('mot'                  ,   'WorkbenchController::mot'              );    
});
```
- refactoring/app/Controllers/WorkbenchController.php
- refactoring/app/Views/workbench/mot.php

- refactoring/app/Views/workbench/libs.php
servira de base , inclue déclaration lib js et style , utilisé par CmsWorkbench mais pas par MotWorkbench
