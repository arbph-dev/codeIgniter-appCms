## Workbench - Phase 1

Objectif

Créer une infrastructure minimale de Workbench qui valide le concept avant de développer un véritable éditeur.

Le premier objectif n'est pas d'éditer le composant, mais de vérifier toute la chaîne :
```
ComponentCatalog
        │
        ▼
ComponentDefinition
        │
        ▼
Workbench
        │
        ├── Descriptor JSON
        ├── Aperçu du composant
        └── API du composant
```
        
### Étape 1 — ComponentCatalogWorkbench

Créer un Workbench générique.

Fonctionnalités :
- liste des composants connus du ComponentCatalog
- sélection d'un composant
- affichage du ComponentDefinition
- affichage du DescriptorDefinition
- affichage JSON formaté

Aucune édition.

**Objectif** : Valider que le Workbench dialogue correctement avec le catalogue.

```
Core
├── ✔ ComponentDefinition
├── ✔ ComponentDefinitionRegistry
├── ✔ ComponentCatalog
│
UI
├── ➜ CatalogPanel
├── DefinitionPanel
├── DescriptorPanel
├── JsonPanel
│
Workbench
└── ComponentCatalogWorkbench
```






### Étape 2 — Preview

Ajouter une seconde zone :

+-------------------+----------------------+
| Descriptor JSON   | Preview              |
|                   |                      |
| {...}             | composant            |
|                   |                      |
+-------------------+----------------------+

Le composant est rendu comme dans le CMS.

Aucune édition.

### Étape 3 — CarouselWorkbench

Premier Workbench spécialisé.

Il exploite simultanément :

ComponentCatalog
Carousel
DescriptorDefinition

Il devient capable d'afficher :

aperçu
JSON
informations techniques

Toujours aucune édition.

### Étape 4 — ImageProvider

Le Workbench reçoit une collection d'images.

Dans un premier temps :

$images = [...];

transmise directement par la vue.

Le Workbench ne sait pas d'où elles viennent.

### Étape 5 — ImageModel

Remplacer progressivement :

Vue
    │
    ▼
ImageModel

Le Workbench continue de recevoir exactement la même structure.

Aucune modification du JavaScript.

### Étape 6 — ImageProvider

Introduire :

ImageProvider

    ▼

ImageModel

Le Provider devient responsable de :

requêtes
filtrage
catégories
pagination
recherche

Le Workbench reste inchangé.

### Étape 7 — CarouselEditor

Seulement après validation complète.

Le panneau de droite devient un véritable éditeur :

ajout d'image
suppression
ordre (drag & drop)
légende
lien
aperçu immédiat

Le JSON est mis à jour automatiquement.

### Étape 8 — Généralisation

Le même modèle sera réutilisable pour :

VoxWorkbench
PDFWorkbench
TimelineWorkbench
ThreeWorkbench
LeafletWorkbench

avec le même principe :

Descriptor
      │
      ▼
Workbench
      │
 ├── Preview
 ├── JSON
 ├── Editor
 └── Providers

Cette progression cohérente introduit les Workbench comme une couche indépendante, capable de recevoir des données (descripteurs, images, connecteurs) sans être couplée à leur origine.
Cela prépare l'arrivée des futurs Providers et Connectors tout en gardant le JavaScript des Workbench stable.
