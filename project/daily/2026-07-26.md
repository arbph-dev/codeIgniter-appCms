## Points traités

### 1. Gestion du bus

**Avant (Iter004)**  
`WorkbenchBase` cherchait le bus dans `config.eventBus || window.bus || null`.  
Fragile : dépend de l'ordre de chargement des scripts et de globals.

**Après (Iter005)**  
```js
// WorkbenchBase.js
import { bus } from '/assets/js/core/eventBus.js';
// ...
this.bus = bus;   // singleton importé directement
```

Façade exposée aux classes filles :
```js
this.publish('cms:article:loaded', { slug });
this.subscribe('cms:section:change', (data) => { ... });
```

`window.eventBusPublish` (héritage bootstrap.js) n'est plus nécessaire.

---

### 2. Gestion des composants — suppression de bootstrap.js

**Avant (Iter004)**  
`setupComponentRegistry()` enregistrait une seule fonction `initCms`  
qui appelait `bootstrap.js/initCms()` — fichier d'essai, couplage fort.

**Après (Iter005)**  
Chaque composant est importé et enregistré individuellement :

```js
// CmsArticleWorkbench.js
import { initApex }    from '/assets/js/components/apex.js';
import { initCallout } from '/assets/js/components/callout.js';
import { initCodeVal } from '/assets/js/components/codeval.js';
import { initLeaflet } from '/assets/js/components/leaflet.js';
import { initMermaid } from '/assets/js/components/mermaid.js';
import { init as initThree } from '/assets/js/components/three/index.js';

setupComponentRegistry() {
    this.register('apex',    initApex);     // ① dépendance codeval
    this.register('callout', initCallout);  // ② indépendants
    this.register('leaflet', initLeaflet);
    this.register('mermaid', initMermaid);
    this.register('three',   initThree);
    this.register('codeval', initCodeVal);  // ③ consommateur d'events
}
```

`bootstrap.js` n'est plus importé.  
L'ordre apex → codeval est préservé (contrainte documentée dans bootstrap.js).

---

### 3. Intégration de domhelper

**Avant (Iter004)**  
`getElement()` utilisait `this.domHelper` (config externe optionnel) ou  
`this.container.querySelector()` brut.

**Après (Iter005)**  
```js
// WorkbenchBase.js
import { qs, qsa, byId, create, clear, toggle } from '/assets/js/core/domhelper.js';

// exposés aux classes filles via this.dom
this.dom = { qs, qsa, byId, create, clear, toggle };

// getElement() utilise qs importé
getElement(selector) {
    return qs(selector, this.container);
}
```

Prochaine étape : `templates.js` et `validation.js` selon le même pattern.

### 4. TabSystem — nouveau composant

**Fichier** : `assets/js/ui/workbench/TabSystem.js`
  https://github.com/arbph-dev/codeIgniter-appCms/blob/main/refactoring/assets/js/ui/workbench/TabSystem.js

Système d'onglets générique, indépendant du CMS.

#### API

| Méthode | Description |
|---------|-------------|
| `addTab(id, label, renderFn, initFn?)` | Ajoute un onglet. Chaînable. |
| `activate(id)` | Active un onglet. Init paresseuse (initFn une seule fois). |
| `render(container)` | Construit nav + panes. Active le premier onglet. |
| `updateTabContent(id, content)` | Met à jour un pane (HTMLElement ou string). |
| `setBadge(id, text)` | Ajoute un badge/compteur au bouton nav. |
| `destroy()` | Vide et libère. |

#### Exemple — sections d'article

```js
// Dans CmsArticleWorkbench (Iter006+)
loadSections(sections) {
    const tabs = this.initTabSystem();
    const container = this.getElement('#wb-content');

    sections.forEach(section => {
        tabs.addTab(
            `section-${section.id}`,
            section.title,
            () => {
                const div = this.dom.create('div', { class: 'cms_section' });
                div.innerHTML = section.content;
                return div;
            },
            (pane) => {
                // init composants de la section au premier affichage
                this.initRegisteredComponents();
            }
        );
    });

    tabs.render(container);
}
```

#### CSS à ajouter dans `workbench.css`

```css
.wb_tabs_nav        { display: flex; gap: 4px; border-bottom: 2px solid var(--wb-border); }
.wb_tab_btn         { padding: 6px 14px; background: none; border: none; cursor: pointer; }
.wb_tab_btn.active  { border-bottom: 2px solid var(--wb-accent); font-weight: bold; }
.wb_tab_pane        { padding: 12px 0; }
.wb_tab_badge       { margin-left: 6px; background: var(--wb-accent); border-radius: 10px;
                       padding: 1px 6px; font-size: 0.75em; }
```

# Iteration 006 — Navigation par sections

## Iter006.1 - En cours
Intégrer TabSystem dans CmsArticleWorkbench pour afficher une section par onglet
- [X] ajouter CSS dans `/assets/css/components/workbench.css`
  https://github.com/arbph-dev/codeIgniter-appCms/blob/main/refactoring/assets/css/components/workbench.css

**`TabSystem.js`** — une seule correction mais critique : 
- `tab.initialized = true` est positionné **avant** l'appel à `initFn()`.
  Sans ça, un double-clic rapide pendant un fetch déclenche deux requêtes parallèles sur la même section. En cas d'erreur (sync ou async), `initialized` est remis à `false` pour permettre un retry.

**`CmsArticleWorkbench.js`** — le `loadFromPHP()` branche maintenant automatiquement :
- `article.sections.length > 1` → mode onglets :
  `loadSections()` construit le TabSystem, le `render()` active le premier onglet, ce qui déclenche immédiatement le premier `fetchSection()`
- sinon → mode plat (comportement Iter005, `$content` PHP direct)

Le paramètre `content` reste passé mais inutilisé en mode tabs — c'est intentionnel, il sert de fallback si un jour les sections ne sont pas disponibles.

`getTabs()` expose le TabSystem pour activation programmatique depuis l'extérieur (`wb.getTabs()?.activate('section-3')`).

**`CmsController.php`** — une seule ligne ajoutée : si `$article['sections']` est vide, appel à `$this->cms->getArticleSections($article['id'])`. **CmsService doit implémenter cette méthode** avec le format `[{ id, title, position }, …]`.
