## Orchestrated CSS reuse strategy
La note documente trois choses qui serviront durablement :

Les variables — tout le monde sait de quoi on parle quand on écrit var(--wb-accent).

Les patterns nommés — header, bouton, ligne, dl, état vide. Quand un nouveau workbench arrive, la checklist dit explicitement ce qui se réemploye et ce qui se redéfinit. Ça évite de réinventer .wb-btn pour la cinquième fois.

Les dépendances sur domhelper — c'est le point le plus fragile : les factories table(), detail(), pagination() génèrent du HTML qu'on styte sans connaître leurs classes internes. C'est documenté explicitement pour que personne ne s'étonne si un refactor de domhelper casse l'apparence.

Pour la suite — "Versatile Knowledge Base" est un bon nom. Il dit ce que le projet fait vraiment : structurer et exposer de la connaissance, pas seulement gérer du contenu. Le workbench layer qu'on construit est cohérent avec ça : c'est l'outillage interne pour travailler sur la base, pas pour la consommer.


# Workbench — CSS Patterns & Conventions

> Fichier : `/assets/css/components/workbench.css`  
> Projet  : Versatile Knowledge Base  
> Thème   : dark (`#0d1117` / `#eee236` / `#0057b8`)

les variables sont disponibles hors du conteneur workbench).

|------------------|-------------|--------------------------------|
| `--wb-bg`        | `#0d1117`   | fond global                    |

| `--wb-border`    | `#30363d`   | séparateurs                    |
| `--wb-text`      | `#c9d1d9`   | texte principal                |
| `--wb-text-muted`| `#8b949e`   | labels, métadonnées            |
| `--wb-accent`    | `#eee236`   | titres, bordure active, badges |

| `--wb-selected`  | `#1f3a5f`   | ligne/item sélectionné         |

## Conventions de nommage

| Contexte            | Préfixe    | Séparateur | Exemple                  |
|---------------------|------------|------------|--------------------------|
| Composants génériques | `wb-`    | tiret      | `.wb-btn`, `.wb-empty`   |
| Système d'onglets   | `wb_tab_`  | underscore | `.wb_tab_btn`            |
| Workbench métier    | `wb_{name}_` | underscore | `.wb_mot_table`        |
| Panels partagés     | `wb_panel_`  | underscore | `.wb_panel_header`     |

> **Règle** : un nouveau Workbench → préfixe `wb_{name}_` pour ses classes spécifiques.  
> Les classes `wb_panel_*` sont partagées entre tous les Workbenches.

---

## Patterns réutilisables

### Header de panel — `.wb_panel_header`

```css
/* Pattern : fond #1a2a4a + bordure accent */
background : #1a2a4a;
border-bottom : 2px solid var(--wb-accent);
```

Utilisé par : `MotListPanel`, `MotDetailPanel`, `DefinitionPanel`, `DescriptorPanel`, `JsonPanel`.

---

### Bouton standard — `.wb-btn`

```css
padding    : 4px 12px;
border     : 1px solid var(--wb-border);
background : var(--wb-panel);
color      : var(--wb-text);
```

États : `.wb-btn:hover` → `var(--wb-hover)` / `.wb-btn--active` → `var(--wb-blue)`.  
**Réemploi** : `.wb_mot_search_btn` et boutons de pagination sont calqués sur ce pattern.

---

### Ligne interactive — `.wb-tree-node`

```css
/* hover  */ background : var(--wb-hover);
/* select */ background : var(--wb-selected);
```

**Réemploi** : `tbody tr:hover` et `tr.is-selected` dans `.wb_mot_table .cp_table`.

---

### Liste de propriétés — `.wb-dl`

```css
display               : grid;
grid-template-columns : 90px 1fr;
gap                   : 3px 8px;
```

`dt` → `var(--wb-text-muted)` / `dd` → `var(--wb-text)`.  
**Réemploi** : `.wb_panel_body dl` (factory `detail()` de domhelper).

---

### État vide — `.wb-empty`

Déjà défini. Utilisé directement par la factory `notice('empty')` de domhelper.  
Ne pas redéfinir — étendre si besoin :

```css
.wb_mot_table .wb-empty { padding: 24px; }
```

---

## Structure WorkbenchBase

```
#xxxWorkbench              ← scoped styles (height, flex direction)
  .wb-header               ← optionnel (display:none si inutilisé)
  .wb-body                 ← flex:1, overflow:hidden
    .wb-content            ← flex:1, overflow:hidden
      .wb_{name}_layout    ← grid ou flex selon le workbench
```

Le layout interne (`grid-template-columns`, etc.) est **toujours scoped** au workbench concerné.

---

## Ajout d'un nouveau Workbench — checklist CSS

- [ ] Scoper sur `#{name}Workbench` : `height`, `flex-direction`, `.wb-body`, `.wb-content`
- [ ] Définir `.wb_{name}_layout` (grid ou flex)
- [ ] Panels : étendre `.wb_mot_list_panel` / `detail_panel` comme référence
- [ ] Header : **réemployer** `.wb_panel_header` sans redéfinir
- [ ] Body : **réemployer** `.wb_panel_body` sans redéfinir
- [ ] Boutons : **réemployer** `.wb-btn` pattern
- [ ] Table dark : override `.wb_{name}_table .cp_table` sur le modèle mot
- [ ] Documenter ici tout pattern **nouveau** introduit

## Dépendances externes

| Fichier               | Fourni par    | Usage dans WB             |
|-----------------------|---------------|---------------------------|
| `cp_table`            | `app.css`     | tables de données         |
| `notice()` classes    | `domhelper.js`| états loading/empty/error |
| `pagination()` markup | `domhelper.js`| ciblé par `.wb_mot_pager button` |
| `detail()` markup     | `domhelper.js`| ciblé par `.wb_panel_body dl`    |

Les factories domhelper génèrent du HTML standard (`table`, `dl`, `button`) —
les styles workbench ciblent ces éléments **sans connaître les classes internes** des factories.
